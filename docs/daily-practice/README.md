# CarePulse Daily Practice

This folder keeps the daily learning and improvement plan for CarePulse. The goal is to make small, genuine improvements while understanding the product problem, the technical design, and the business value behind each change.

## Why this project matters

CarePulse focuses on customer-experience recovery. Many support teams handle tickets, calls, follow-ups, and feedback, but the hard part is knowing which customer is quietly becoming unhappy, which promise is delayed, and which case needs attention before it becomes an escalation.

This project is a way to study that problem through a practical software system: risk signals, sentiment movement, recovery actions, dashboards, and role-based workflows.

## Daily routine

1. Pick one small task from `task-bank.md` or the daily starter.
2. Read the related file or feature area first.
3. Make a small real improvement.
4. Run or inspect the change.
5. Add one short note to `progress.md`.
6. Commit with a clear message.

## Working rule

Every commit should represent a real improvement: code, tests, documentation, demo data, validation, analytics explanation, or project understanding. Avoid empty commits, random formatting, or changes that cannot be explained.

## Main learning areas

- Python and FastAPI backend flow
- Jinja pages and user-facing dashboards
- SQLAlchemy models and SQLite/PostgreSQL setup
- Risk scoring, sentiment, recovery, and analytics logic
- pytest checks and API testing
- Security, deployment, and production-readiness notes
- Business explanation for customer support and service recovery
